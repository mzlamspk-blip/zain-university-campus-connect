Zain University – Campus Connect

Project Report: Analysis, Fixes, Technology Stack & Verification
Flask + MongoDB (Atlas) University Campus Portal  ·  Report generated: 21 November 2026

1. What this project is

Campus Connect is a web portal for a university campus that lets students report problems, find lost items, join campus events and take part in moderated discussions, while administrators manage students, moderate content, respond to complaints and view analytics.

Student portal
Registration/login, complaints with images, Lost & Found, events, discussions with likes/upvotes/comments, profile & password change, notifications.
Admin portal
Dashboard with statistics, complaint responses, student activate/deactivate, post moderation & report review, event management, analytics charts, settings.
Public site
Landing page with features, about section and the next 3 upcoming events, plus a /health database status endpoint.

3. Errors found and how they were resolved

#Error / problemSolution applied
1Unknown database 'zain_university' – the app could not start Created the database and all 12 tables from database.sql.
2MySQL 1055 ONLY_FULL_GROUP_BY – admin dashboard/analytics returned HTTP 500 Rewrote the monthly-complaint and student-registration queries to group by the selected expressions.
3CSRF session token missing (HTTP 400) All forms verified to carry the hidden token; empty-field login now shows a clear message; a friendly 400 page explains that the form session expired and asks the user to reload.
4Connection refused in the browser Transient – the server was being restarted to apply a fix. Verified /health returns 200 {"database":"connected"} after restart.
5"Invalid login details" with empty fields Login now validates empty username/password first; portal selection (Student/Admin) must match the account.
6Weak default FLASK_SECRET_KEY ("dev-only-change-this-secret") Rotated to a 64-character random key; the app now auto-generates a strong key if the configured one is missing or weak.
7Debug mode ON (app.run(debug=True)) – debugger can allow remote code execution Debug is off by default; FLASK_DEBUG=1 opts in for local development only.
8Deactivated students could keep using an open session login_required() now re-checks the account in the database on every request, so deactivation is immediate.
9Uploaded images were public in static/uploads/ and only checked by file extension Moved uploads to uploads/ (outside static), added file-signature (magic byte) validation, random UUID filenames, and an authenticated /media/<file> route that only lets the owner or an admin view an image. Event banners stay public via /media/events/<file>.
10Post "report" silently hid any post (abuse possible) and had dead code New post_reports table with one report per student per post, a reason field, an admin review page with Take-down / Dismiss actions, and no automatic un-approval.
11No brute-force protection; unvalidated e-mail at registration Login throttling (5 failures per 10 minutes per IP+identity) and email-validator on registration.
12State-changing GET routes (/logout, /notifications) Both converted to CSRF-protected POST forms.
13Admin account only created when running python app.py Bootstrap moved to import time, so WSGI deployments also create the configured admin (idempotent).
14Lost & Found exposed every student's e-mail address passively E-mail is now revealed only through an explicit "Show contact" action.
15Orphaned upload files, unsafe LIKE wildcards, deprecated utcnow(), duplicate student IDs Uploads deleted with their records, search terms escaped, UTC date code removed, unique student-ID column added.

7. How to run the final project

  1. Extract zain-university-final.zip and open the folder in VS Code.
  2. Create/activate the virtual environment: python -m venv .venv then .\.venv\Scripts\Activate.ps1.
  3. Install packages: pip install -r requirements.txt.
  4. Create the collections and indexes in MongoDB: python mongo_init.py.
  5. Copy .env.example to .env and fill in the MongoDB Atlas connection string, admin account and a long random FLASK_SECRET_KEY.
  6. Start the site: python app.py → open http://127.0.0.1:5000.
  7. Optional: run python smoke_test.py to re-verify all 42 checks.
Admin access: the administrator account is created automatically on first run from ADMIN_USERNAME / ADMIN_EMAIL / ADMIN_PASSWORD in .env. On the login page choose Admin portal. Security reminder: change the current password and the Atlas database password, and never commit .env to GitHub.

8. Security hardening included in the final version

  • CSRF token on every form; logout and notification-read are POST-only.
  • Werkzeug password hashing; parameterised SQL everywhere; role checks on all protected routes.
  • Strong random session key; HttpOnly + SameSite=Lax cookies; optional SESSION_COOKIE_SECURE.
  • Login throttling, e-mail validation, immediate session revocation on deactivation.
  • Private authenticated image serving, magic-byte upload validation, random filenames, 5 MB limit.
  • Report moderation queue with audit records; LIKE-wildcard escaping; orphan file clean-up.
